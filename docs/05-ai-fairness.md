# AI와 공정성

## 1. 원칙

공정성 판단과 투표 결과는 항상 같은 입력에 같은 결과를 내는 코드가 담당한다. Bedrock은 비정형 텍스트 구조화, 사용자 설명, 결정론 검색이 실패했을 때 허용된 제약 완화 선택에만 사용한다.

AI는 일정을 직접 저장하거나 투표 결과를 변경할 권한이 없다. AI 출력은 코드 검증을 통과한 뒤에만 후보로 공개한다.

## 2. 후보 생성 파이프라인

1. 영향받는 슬롯과 사용 가능한 시간 범위를 계산한다.
2. 기상·지역·시간·예산 등 하드 제약을 만든다.
3. TourAPI `KorService2`에서 대전 후보를 조회한다.
4. 거리순으로 1차 압축하고 ODsay로 이동시간을 계산한다.
5. 운영시간 자연어는 Bedrock 구조화 출력으로 한 번 해석한 뒤 코드가 시간 적합성을 검증한다.
6. 멤버별 만족도와 그룹 공정성 순위를 계산한다.
7. 서로 다른 성격의 상위 후보를 최대 3개 선택한다.
8. Bedrock이 검증된 사실만 사용해 설명문을 생성한다.

## 3. 만족도 계산

각 하위 점수는 0~100으로 정규화한다.

```text
memberUtility =
  categoryMatch × 0.35
  + budgetFit × 0.25
  + travelFit × 0.20
  + energyFit × 0.20
```

- `categoryMatch`: 선택 범주와 중요 기준의 일치도
- `budgetFit`: 개인 예산 이내면 100, 초과 폭에 따라 선형 감소
- `travelFit`: 개인 이동 허용도 대비 추가 이동시간
- `energyFit`: 활동 강도와 현재 피로 성향의 일치도

후보는 아래 튜플을 내림차순으로 비교한다.

1. 모든 멤버 중 최저 `memberUtility`
2. `weight = 1 + concessionScore / 100`을 적용한 가중 평균 만족도
3. 더 짧은 총 이동시간
4. 정렬 가능한 안정적 후보 ID

따라서 평균이 높더라도 한 사람의 만족도가 지나치게 낮은 후보는 먼저 탈락한다.

## 4. 양보 원장

일정 확정 후 각 멤버에 대해 다음 값을 계산한다.

```text
regret = max(제시된 후보의 개인 만족도) - 확정 후보의 개인 만족도
newConcessionScore = clamp(0, 100, oldConcessionScore × 0.7 + regret)
```

오래된 양보는 점차 감소하고 최근에 선호가 덜 반영된 멤버는 다음 후보 순위에서 더 큰 가중치를 가진다. 개인 점수나 이름은 그룹에 공개하지 않는다. 동률 투표는 동률 후보만 대상으로 같은 순위 튜플을 적용한다.

## 5. Agent 호출 조건

결정론 검색으로 서로 다른 유효 후보 3개를 만들지 못한 경우에만 Agent를 호출한다. Agent가 반환할 수 있는 동작은 다음 enum으로 제한한다.

- `EXPAND_RADIUS`: 검색 반경 확대
- `RELAX_CATEGORY`: 선호 범주 하나 완화
- `RELAX_BUDGET`: 예산 상한을 정해진 비율만큼 완화
- `SHIFT_TIME`: 슬롯 시작 시각 이동
- `REMOVE_SLOT`: 해당 슬롯 삭제를 하나의 후보로 제안

한 번에 하나의 완화만 적용하고 코드가 재검색한다. 서로 다른 후보 3개를 확보하거나 5회 시도하면 종료한다. 하드 제약인 대전 지역, 실제 운영 여부, 그룹 승인, 개인정보 보호는 완화할 수 없다.

## 6. Bedrock 계약

- 모델 ID는 환경설정으로 주입하고 Converse API의 JSON schema 출력을 사용한다.
- 입력에는 익명 멤버 번호, 정규화 점수, 집계 제약만 제공한다. 이름과 원본 응답은 제공하지 않는다.
- 운영시간 해석 결과는 `open`, `close`, `breaks`, `lastEntry`, `confidence`, `sourceText` 구조다.
- 설명 결과는 `title`, `summary`, `changes`, `tradeoffs`, `unknowns` 구조다.
- Agent 결과는 `action`, `targetConstraint`, `amount`, `reasonCode` 구조이며 자유 실행 명령을 허용하지 않는다.
- 모델 temperature는 0에 가깝게 설정하고 입력·출력 크기와 여행당 호출 횟수 상한을 둔다.

## 7. 실패와 안전장치

- Bedrock 장애 시 코드 후보와 템플릿 설명으로 계속 진행한다.
- 외부 정보가 없으면 `정보 없음`으로 유지하고 모델이 채우지 못하게 한다.
- AI 출력에 등장한 장소·가격·시간은 원본 외부 데이터와 다시 대조한다.
- 검증된 후보가 1~2개뿐이면 그 수만 제공하고 이유를 안내한다.
- 후보가 전혀 없으면 원본 일정을 유지하고 방장에게 수동 편집을 제안한다.

## 8. 평가 세트

대전의 맑음, 폭우, 단일 휴관, 후보 부족, 예산 충돌, 이동시간 충돌, 동률 투표를 포함한 고정 시나리오를 만든다. 배포 전 다음을 만족해야 한다.

- 같은 입력의 후보 순위와 동률 결과 100% 재현
- 존재하지 않는 장소·가격·운영시간 생성 0건
- 구조화 출력 schema 통과율 99% 이상
- 개인 원본 선호가 프롬프트·로그에 포함된 사례 0건
